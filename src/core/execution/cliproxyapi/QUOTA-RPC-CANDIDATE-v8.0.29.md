# Candidate quota plugin integration — v8.0.29

Source: router-for-me/CLIProxyAPI `5fc580b1d72d87a7bcfe5cfb6f479c1aea5625b3`, `internal/pluginhost/quota_provider.go`, `internal/pluginhost/rpc_client.go:646–671`, `sdk/pluginabi/types.go:90–93`, and `internal/api/handlers/management/plugin_quota.go`. This builds on the typed quota SDK and normalization in #749. The accepted upstream pin is unchanged.

Quota-only process plugins can register their identifier and describe/fetch/reset ABI. Fetch/reset lease a private HTTP client already scoped to the selected account. Missing authority denies HTTP rather than using a broader host client. Quota leases allow only HTTP callbacks and logging; they cannot invoke registered auth-store or model mutation callbacks. The client handle never crosses JSON. Dropping or timing out the call revokes its context, cancels running HTTP and closes its HTTP streams; stream ownership includes the call identity.

Host discovery follows two passes over priority-sorted records: direct quota identifier/plugin ID/auth identifier, then supported-provider aliases. Concurrent alias queries share one successful description per immutable snapshot. Failed or canceled descriptions remain retryable, and plugin reloads cannot publish stale maps or reuse old caches. Plugin calls have a fixed 30-second bound, with no runtime environment switch.

Authenticated management transport exposes `GET /v0/management/quota/providers`, `POST /quota/fetch`, `POST /quota/reset`, and the plugin-specific GET/POST/DELETE `/plugins/:id/quota` and POST `/plugins/:id/quota/reset` variants under the same management prefix. `attach_plugin_quota_service` takes an injected server credential source, plugin host and host summary. `with_probe` and `with_routing_reset` supply the existing typed probe and cooldown authorities. Body input selects a public account index; it cannot supply credential storage, HTTP authority or probe URLs. A mismatched account context fails before the plugin or probe is called.

A successful provider reset must precede the routing cooldown reset. Declines, RPC errors and timeouts preserve cooldown state. Errors are typed and redact plugin/provider bodies. Credential-store or pre-request transport errors are not provider auth denials; actual probe upstream status is retained separately. Aggregate asynchronous management work also has a 30-second bound. Synchronous injected credential/probe authorities must retain their existing bounded store/network policy.

Unit and protocol tests do not establish account validity, live limit availability or installed acceptance.
