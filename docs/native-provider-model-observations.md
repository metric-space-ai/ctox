# Native account model observations

The Owner/Admin command `ctox.workjet.providers.observe_native` accepts only a logical account ID and its current account revision. It resolves the adopted native main account on the actual holding instance and uses the same stored route and secret selector as the operator model probe. The bounded GET /models executes outside the policy transaction and uses the configured upstream endpoint. Discovery shares the stored provider, model and secret selection with inference, while Pi keeps its existing internal inference edge. Discovery resolves current runtime state without the inference-kernel endpoint cache and checks the endpoint/credential pair before disclosure and again after the request; the command checks the current owner, holder, provider and account revision before committing.

Only safe observed model IDs, the last successful time, and allowlisted response metadata are persisted. No key, private selector, endpoint, raw provider response or configured model becomes part of the instance list. A new revision has no inherited catalog authority. Native metadata refresh compares a holder-private configuration/credential fingerprint: a changed credential or endpoint advances the same logical account's revision and invalidates its old catalog, while preserving account identity and withdrawals. The observation is checked against that private binding before commit. The fingerprint stays in the native policy store and is omitted from serialized observations and the instance list; future holder dispatch must still validate the current private route around actual execution. Failed attempts preserve last-known real IDs, mark them non-fresh and expose the actual response code or transport failure separately. They never disable the account, change its cooldown, rotate credentials or move sessions.

A successful observation is fresh for at most 24 hours. This is discovery metadata; it never proves quota, a successful Hi check or permission for later inference. The list always keeps inferenceVerified false. Actual holder dispatch must still validate current consumer membership, withdrawal, account/model/route binding and execution authority. Subscription and remote-holder catalog adapters and the unified Workjet consumer remain separate slices.

Validation covers a real loopback GET through an isolated native runtime/secret-store configuration, unchanged private state, redacted output, owner/holder/revision selection, stale and failed cache retention, and rejected unadmitted/private caller payloads. Installed acceptance remains with the normal product driver after merge and native delivery.

## Gateway inference failures

Claude Responses distinguishes local selection failures from upstream responses. Local HTTP503 errors identify `error.source: gateway` and a `gateway_account_*` code for missing candidates, ineligible accounts, gateway cooldown or account-state storage failure. A cooldown carries the scheduler's absolute Unix-millisecond `retry_at_ms`; it is not evidence that the provider rejected credentials. Buffered and streaming pools preserve an actual upstream failure if every remaining fallback account is ineligible. State-storage failures still fail closed. This portable repair matches Workjet PR375; the historical installed0.0.76 generic503 remains unclassified until a new authorized installed run is measured.

## Consumer-bound manual model probes

The native Claude Hi adapter accepts an actual `AdmittedConsumerAuthority`, a logical account revision and a live selected model. It uses the same holder-private account/credential reservation as the native Supervisor, requires the local holding instance, and sends an exact-account request through the existing Responses gateway. The total probe is bounded at20 seconds, including slot wait, with at most two concurrent requests, a128 KiB body limit, no redirects, and current account/consumer checks around waits and completion. Drop cancels the actual in-flight transport; no detached probe is started. The generated text and private account selector never enter the allowlisted result. It neither creates a project/meeting turn nor administratively changes runtime defaults, account enablement or existing session affinity. Normal gateway authentication refresh and upstream-outcome processing remain active; a changed private binding invalidates the in-flight check.

The gateway now supplies a request-scoped `X-CTOX-Upstream-Status` only when its executor records a real provider response. A model check needs an exact account acknowledgement and that status witness. Gateway wrapper HTTP codes alone cannot establish expired credentials, provider denial or model-not-found. Local account/state/cooldown errors remain gateway-unavailable outcomes even if an earlier attempt produced an upstream witness. The guarded native receiver is `ctox.workjet.models.check.v1`. It accepts exactly one request `{version:1, op:"check", commandId, accountId, accountRevision, modelId}` and captures authority from the actual accepted peer and transport-held token. Caller owner, computer, credential, endpoint, root, project and meeting fields are rejected. It retains the original private account generation through the request, stores only the closed probe result in the existing native provider-policy store, and returns a correlated guarded response. Persistence and physical publication both revalidate current consumer/account/model state plus the prepared encrypted-record generation, without transport or secret API reentry under their native fences. Network waits occur outside those fences.

The existing account list adds `modelChecks`, scoped to the account revision, without changing catalog-only `inferenceVerified:false`. The native policy store is the sole observation writer; no new RxDB projection chain is introduced. Older completions cannot overwrite a newer observation, account deletion cascades to its checks, and raw database JSON is never returned. The shell exposes the transient `instance.providers.models.check` action through the advertised `ctox-workjet-model-check-v1` capability. It forwards only the closed check DTO to the admitted native channel, discards replies after owner/instance/session replacement, validates account/model/request correlation, and strips private unknown fields. Both browser and native requests are bounded. Other provider adapters, remote-holder checks, Workjet renderer delivery and installed acceptance remain separate and are not claimed by this native Claude change.
