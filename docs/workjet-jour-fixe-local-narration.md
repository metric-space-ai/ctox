# Local Jour fixe narration custody

`ctox.workjet.jour_fixe.narration.local_publish` is an explicit authenticated Owner control through the existing `business_commands` WebRTC path. It consumes an already uploaded `desktop_files`/`desktop_file_chunks` WAV. It does not call an Apple or gateway provider and cannot construct `VerifiedSpeechOutput`.

Request (`LocalNarrationRequest`): `operation_id`, native `instance_id` (`biz_…`, not Workjet's `managed:…` alias), `project_id`, `meeting_id`, `deck_revision`, `expected_revision`, `slide_id`, source `file_id`, exact `generation_id`, `audio_sha256`, `narration_text_sha256`. The command's `record_id` must be the project. The narrated text is the **exact stored slide `body_markdown`**, at most 4096 UTF-8 bytes; the desktop/helper must synthesize that string and hash it unchanged.

Upload the real helper WAV through the existing file/chunk bridge before this command. The source file requires an explicit `owner_id` resolving to the same verified canonical Owner, active matching generation, byte SHA256 scheme, complete bounded chunks, and current native read/write policy on both file collections. No URL, arbitrary host path, provider name, caller duration, owner or readiness flag is accepted. Native reconstruction is one read-only SQLite snapshot; content is limited to 8 MiB. RIFF/WAVE PCM (16/24/32-bit integer or 32-bit float, mono/stereo, 16/22.05/24/44.1/48 kHz) is checked structurally and its duration is derived from frames, capped at five minutes.

The existing native domain transaction freezes a separate file and its chunks in the authoritative record store, binds its new `AudioRef` to the exact slide/deck/operation/text/audio hashes, and commits the meeting plus the application receipt together. Mutable/deleted original uploads are unnecessary on replay. Projection recovery republishes the exact retained native copy over the normal data plane. A failed receipt commit leaves no copied file, chunks or meeting mutation. A slide is written once per draft; preparing another deck is required to replace narration. The deck stays `preparing` until every stored slide has actual audio; only then can the existing Owner start control enter `live`.

Response `result.local_narration` (`LocalNarrationReceipt`) includes exact operation/instance/project/meeting/deck/slide/canonical Owner/revision, actual persisted `audio`, timestamp, `provenance: authenticated_owner_local_audio` and `provider_verified: false`. Its AudioRef carries the same explicit provenance and immutable native generation. `source_run_id` is this local publication operation, `model` is `owner-uploaded-local-audio`, and `synthesis_duration_ms` is zero (not measured, no provider timing asserted). These are local custody metadata, never a gateway run/model or Apple attestation. The separate native gateway speech proof remains private and unchanged.

Current authentication, canonical ownership, active project, registered Supervisor, exact deck/text and allowed meeting state are rechecked on replay and domain recovery. Closed/stale/rebound/revoked scopes fail. The desktop remains responsible for signed-helper verification, real synthesis, playback, byte upload, exact receipt checks, and installed acceptance. Models measures synthesis/latencies; Main owns Blob/preload/room integration. This API does not itself pass the conditional Saturday fallback or the live Monday meeting acceptance.

The Shell control action is `project.jour_fixe.narration.local_publish`, with `projectId`, `meetingId`, `operationId`, `expectedRevision`, `slideId`, `fileId`, `generationId`, `deckRevision`, `audioSha256`, and `narrationTextSha256`. It derives the native instance from the current sync configuration; caller-supplied instance, Owner, provider/model, duration or readiness flags are rejected. The bridge waits for the existing typed command result and checks the unchanged session/instance, exact correlated native receipt, explicit local provenance, `provider_verified: false`, and actual copied AudioRef before returning `{meeting, mutation, localNarration}`. No HTTP data or speech fallback is introduced. Main still owns signed-helper invocation, upload and room playback; native and browser fixtures cover receipt corruption and cross-instance replacement.
