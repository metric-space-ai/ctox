Das Konzept in vier Schichten

1 · Projekt = virtuell

workjet_projects: Name, Besitzer, kein Pfad. Repliziert per RxDB/WebRTC an jede angemeldete App. Steht.

2 · Working Copy = physisch

workjet_working_copies: project_id, computer_id, Pfad, active. Core behandelt Pfade als opake Gast-Kennungen. Steht, seit 21:54 live.

3 · Session bindet an Working Copy

Jede App (Desktop, Fold) ist Steuerpult. Worker läuft dort, wo die Working Copy liegt. Blockiert: Shell gated an altem Projektbegriff, kein aktiver Computer.

4 · Übertragung

Session pausieren, Arbeitsbaum per Git oder Kopie übertragen, mit neuer working_copy_id fortsetzen, Worker am Ziel neu starten, Kontext aus CTOX nachladen. Workjet-Tools in allen Harnesses sind die Bedienoberfläche. Nicht modelliert.
