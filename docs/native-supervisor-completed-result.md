Reply text and model/request/message IDs come from that native observation. SDK callbacks cannot provide reply text, actual/terminated flags, credentials or authority.

The immutable Core receipt separates configured Luma/route/revision from observed harness/computer/account/model and original SDK/native model correlations. No private account selector or token is serialized. A recorded completion immediately prevents new model sessions and requests for that controller.

Pending/capacity probes, failed sends and retired authority do not publish a result. It then follows its ordinary review and command/queue finalization. SDK turn IDs remain separate from native command/task/attempt correlation; this change does not replace the Owner's original execution identity.
